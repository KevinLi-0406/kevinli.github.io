Mysav Auto-Repush Logic

Background

Mysav: A repair center that now pushes directly to D365 (previously via B2X).
Key Difference: We provide a WO status query API, allowing Mysav to check real-time status before repushing.
Status Flow: Create → Under Repair → Repair Complete → Unit Ship Back
Stock Deduction: Executed on our side when RC is received. Takes up to 1 minute.

Problem Scenarios

Scenario 1: RC deduction fails → WO stays at Under Repair → USB arrives → Error: "Cannot skip RC"
Scenario 2: RC triggers deduction but USB arrives before completion → Error: "Stock deduction still processing"
Out of Stock: If deduction fails, WO stays at Under Repair. We adjust inventory manually, then wait for Mysav's next repush.

Auto-Repush Logic (Frequency: +24H)

Advantage: With WO status query API, Mysav can query real-time status and route precisely, avoiding blind retries. 
flowchart TD
    START([ Mysav pushes status to D365 ]) --> PUSH[Push fails]
    PUSH --> ERR{Error message?}

    ERR -->|Cannot skip Repair Complete| RC[Repush Repair Complete]
    RC --> RCOK{Success?}
    RCOK -->|Yes| NEXT[Continue pushing next status]
    RCOK -->|No| WAIT24

    ERR -->|Stock deduction still processing| QUERY[Query WO status]
    QUERY --> STATUS{WO Status?}
    STATUS -->|= Repair Complete| USB[Repush Unit Ship Back]
    USB --> USBOk{Success?}
    USBOk -->|Yes| NEXT
    USBOk -->|No| WAIT24

    STATUS -->|≠ Repair Complete| RC

    WAIT24[Wait +24H] --> PUSH

Logic Explanation

Error Received Action Rationale
Cannot skip Repair Complete Repush RC Same as B2X: after 24H, deduction has completed. If out of stock, RC repush loops until inventory is adjusted.
Stock deduction still processing Query WO status first If WO = RC: Deduction succeeded, repush USB directly.
If WO ≠ RC: Deduction failed (out of stock), repush RC. After inventory adjustment, next RC repush succeeds.

Key Points

✅ Stock deduction completes within 1 minute, so 24H interval is sufficient
✅ No risk of duplicate deduction (24H ≫ 1min)
✅ WO status query API enables precise routing, avoiding unnecessary retries
✅ If out of stock, RC repush loops until inventory is adjusted by our team
