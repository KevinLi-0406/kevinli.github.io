## 一、背景与痛点

### 现状

Kevin 就职于**九号公司（Ninebot / Segway）**集团信息化中心海外销服系统部，担任应用工程师。日常工作中同时使用 **4 个通讯/协作平台**：

| 平台 | 使用场景 | 日均消息量 | 备注 |
|------|---------|-----------|------|
| **企业微信** | 国内内部沟通（主力） | 100+ 条 | 大多数公司内部都在用 |
| **飞书** | IT 部门试点 | 不定 | IT 部门先行试用 |
| **Microsoft Teams** | 与欧洲团队交互 | ~100 条 | 荷兰时区（CET，北京时间 -7h），英文沟通 |
| **网易企业邮箱** | 内外部邮件 | 4-5 封 | 需求沟通和项目沟通为主 |

### 核心痛点（按优先级排序）

1. **知识沉淀困难（G）**：项目经验、业务规则散落在不同地方，难以检索和复用。**目标：构建完善的个人知识库，且数据完全归自己所有。**
2. **AI 代答（D）**：同事反复问同样的问题，需要人工逐一回答。**目标：用 AI Bot 替我回答，节约时间。**
3. **日报周报（E）**：每天/每周要手动整理工作内容。**目标：AI 自动生成。**
4. **消息遗漏（B）**：重要消息被淹没在不同平台中，事后才发现。
5. **跨平台效率低（C）**：不知道哪个平台有最新消息，频繁切换。

### 终极目标

> 构建一个**统一信息平台 + 个人知识库 + AI Bot** 系统，让 AI 替我回答常见问题，释放我的时间。知识库数据必须**个人所有、可迁移、不依赖任何公司平台**。

                    九号内部 (EU SPP)

## 四、架构设计方案

### 核心理念：「一个大脑，四个触角」

```
┌─────────────────────────────────────────────────┐
│                  统一大脑                          │
│                                                   │
│  ──────────┐  ┌──────────  ┌───────────────┐  │
│  │ 个人知识库 │  │ 智能体   │  │  GitHub 仓库   │  │
│  │ (核心)   │  │ (AI Bot) │  │ (备份+展示)   │  │
│  └──────────┘  └──────────┘  └───────────────┘  │
│                                                   │
├───────────────────────────────────────────────────┤
│                    四个触角                         │
│                                                   │
│  企微 ──► 飞书 ◄──► Teams ◄──► 邮箱             │
│  (国内)    (试点)    (欧洲)      (外部)           │
│                                                   │
└───────────────────────────────────────────────────┘
```

### 关键设计决策

1. **知识库选型**：不使用飞书知识库（绑定公司），选择**本地 Obsidian + GitHub 私有仓库**，数据 100% 个人所有。
2. **AI 引擎**：Cherry Studio 作为主引擎（已跑通飞书+企微），WorkBuddy（腾讯）作为企微侧补充。
3. **数据流**：四个触角 → Cherry Studio AI → 检索个人知识库 → 生成回答 → 推送到对应平台。
