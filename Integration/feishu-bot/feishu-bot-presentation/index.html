// part 03 · architecture

技术架构：WebSocket + Dify

🔌 连接层

WebSocket 长连接

飞书 SDK 的 WSClient 模式，无需公网 IP，无超时限制。消息实时推送，延迟 1-3 秒。

🧠 AI 层

Dify Chat API

内网自建（http://10.232.5.5），支持多轮对话。知识库来源：Markdown 文档 + 业务 PDF/Office。

📦 数据层

知识库热重载

监听文档文件变化，自动重新加载。无需重启 Bot，文档更新即时生效。

🔐 安全层

授权白名单

邮件操作（IMAP/SMTP）仅对授权用户开放。按 senderOpenId 控制权限。

技术架构分四层。

连接层：用飞书 SDK 的 WebSocket 长连接模式。这个方案的关键优势是——无需公网 IP，无超时限制，消息实时推送。对比传统的轮询方案，API 调用量从每天 720 次降到按需调用。

AI 层：用 Dify 作为 AI 引擎，内网自建。飞书和企微 Bot 共用同一个 Dify 应用，支持多轮对话。知识库来源是 Markdown 文档和业务 PDF/Office 文件。

数据层：知识库支持热重载。脚本监听文档文件变化，自动重新加载。文档更新后无需重启 Bot，即时生效。

安全层：邮件操作（IMAP/SMTP）仅对授权用户开放。通过 senderOpenId 白名单控制权限，非授权用户请求会被拒绝。

接下来看核心功能。

// part 04 · features

核心功能：三大能力

01
实时智能问答

群聊 @机器人 提问 → 1-3 秒内回复。支持多轮对话（30 分钟会话保持），引用原消息回复，贴 ❤️ 表情表示已收到。

02
邮件操作（授权白名单）

授权用户可请求：查邮件、搜索邮件、读第 N 封、发邮件。通过 IMAP/SMTP 执行，非授权用户自动拒绝。

03
会话隔离 + 去重

按 senderOpenId:chatId 维护 conversation_id，不同聊天场景互不干扰。Set 缓存最近 1000 条消息，防止重复处理。

核心功能有三个。

第一，实时智能问答。用户在群里 @机器人 提问，1-3 秒内回复。支持多轮对话，30 分钟会话保持。机器人会先贴一个 ❤️ 表情表示已收到，然后引用原消息回复。这个体验很流畅，用户感觉像在跟一个真人对话。

第二，邮件操作。授权用户可以 @机器人 说"查最近 10 封邮件"、"搜索 xxx 的邮件"、"发邮件给 yyy"。机器人通过 IMAP/SMTP 执行。这个功能仅对授权用户开放，非授权用户请求会被拒绝。

第三，会话隔离 + 去重。按 senderOpenId:chatId 维护 conversation_id，不同聊天场景互不干扰。比如你在 A 群问的问题，不会影响到 B 群的对话上下文。同时用 Set 缓存最近 1000 条消息，防止重复处理。

Q&A · 常见问题

Q: 连接失败怎么办？

检查 App Secret 是否正确，确保在飞书后台选择了"长连接"模式（非 Webhook）。

Q: 如何后台常驻运行？

推荐用 pm2：
pm2 start feishu-bot.js --name feishu-bot

Q: 文档更新后需要重启吗？

不需要。脚本监听文档文件变化，自动重新加载知识库。

Q: 这套方案能复用到其他团队吗？

可以。核心是 Dify + WebSocket，换知识库和 App Secret 即可。
