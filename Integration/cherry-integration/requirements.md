# Cherry 与飞书、企微打通 - 需求文档

## 1. 项目背景

### 1.1 现状分析
用户同时使用多个通讯工具（飞书、企业微信、微信）和邮件系统，导致：
- 消息分散，需要频繁切换应用
- 重要信息容易遗漏
- 待办事项分散在不同平台
- 缺乏统一的消息总结和检索

### 1.2 解决方案
通过 Cherry Studio AI 助手作为中枢，整合所有平台的消息，提供：
- 统一的消息查看界面
- AI 智能总结和分类
- 跨平台待办管理
- 一键式消息检索

## 2. 功能需求

### 2.1 核心功能

#### F1: 消息读取
- **F1.1**: 读取飞书所有群聊消息 ✅
- **F1.2**: 读取飞书私聊消息 ✅
- **F1.3**: 读取企业微信消息 ⚠️ (需公司启用)
- **F1.4**: 读取微信消息 (后续)

#### F2: 邮件集成
- **F2.1**: 读取飞书邮件收件箱 ⚠️ (需权限)
- **F2.2**: 获取邮件摘要（发件人、主题、时间）
- **F2.3**: 读取邮件正文内容
- **F2.4**: 发送邮件（后续）

#### F3: 待办管理
- **F3.1**: 读取飞书待办事项 ⚠️ (需权限)
- **F3.2**: 创建待办事项
- **F3.3**: 完成/删除待办
- **F3.4**: 企业微信待办汇总 ✅

#### F4: 消息搜索
- **F4.1**: 关键词搜索消息 ⚠️ (需权限)
- **F4.2**: 按时间范围筛选
- **F4.3**: 按发送者筛选
- **F4.4**: 按群组筛选

#### F5: 智能总结
- **F5.1**: 每日消息摘要生成
- **F5.2**: 重要消息标记
- **F5.3**: 消息分类（工作、个人、通知等）
- **F5.4**: 待办事项提取

#### F6: 日程管理
- **F6.1**: 飞书日程创建 ✅
- **F6.2**: 企业微信日程创建 ✅
- **F6.3**: 跨平台日程查询 ✅

#### F7: 会议管理
- **F7.1**: 飞书会议创建 ✅
- **F7.2**: 企业微信会议创建 ✅
- **F7.3**: 会议链接生成 ✅

### 2.2 高级功能（后续版本）

#### F8: 实时通知
- **F8.1**: 重要消息实时推送
- **F8.2**: 定时摘要推送
- **F8.3**: 紧急消息提醒

#### F9: 数据分析
- **F9.1**: 消息统计（数量、频率）
- **F9.2**: 联系人互动分析
- **F9.3**: 工作时间分析

#### F10: 自动化
- **F10.1**: 自动回复（基于 AI）
- **F10.2**: 消息自动分类
- **F10.3**: 工作流自动化

## 3. 非功能需求

### 3.1 性能需求
- 消息读取延迟：< 5 秒
- 搜索响应时间：< 3 秒
- 摘要生成时间：< 10 秒

### 3.2 安全需求
- 用户凭证加密存储
- API 访问权限最小化
- 敏感信息不记录到日志

### 3.3 可用性需求
- 支持命令行操作
- 支持 Cherry Studio MCP 调用
- 提供清晰的错误提示

## 5. 技术约束

### 5.1 平台限制
- 微信个人号 API 受限，可能需要第三方方案
- 企业微信部分功能需要管理员权限
- 飞书权限需要管理员审批

### 5.2 数据限制
- GitHub 单文件最大 100MB
- 飞书 API 速率限制：5000 次/小时
- 邮件附件大小限制

## 7. 风险与应对

### 7.1 权限审批风险
- **风险**：管理员拒绝部分权限申请
- **应对**：准备降级方案，使用机器人身份替代

### 7.2 API 限制风险
- **风险**：API 调用频率超限
- **应对**：实现请求队列和缓存机制

### 7.3 数据安全风险
- **风险**：敏感消息泄露
- **应对**：本地存储，加密敏感数据

### 7.4 企业微信限制风险
- **风险**：公司未启用消息 API
- **应对**：使用 aibot 方式发送消息，功能受限但可用
