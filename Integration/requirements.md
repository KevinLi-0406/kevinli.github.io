# Cherry 与飞书、企微打通 - 需求文档

> **最后更新**：2026-09-09（新增 F11 Dify AI 引擎集成、同步 F1.1/F1.2 WebSocket 实时模式、F2.1 飞书邮件已激活）

## 1. 项目背景

### 1.1 现状分析
用户同时使用多个通讯工具（飞书、企业微信、微信）和邮件系统，导致：
- 消息分散，需要频繁切换应用
- 重要信息容易遗漏
- 待办事项分散在不同平台
- 缺乏统一的消息总结和检索

### 1.2 解决方案
通过 Cherry Studio AI 助手作为本地操作中枢 + Dify 作为云端 AI 引擎，整合所有平台的消息，提供：
- 统一的消息查看界面
- AI 智能总结和分类
- 跨平台待办管理
- 一键式消息检索
- 群聊 @机器人 实时问答（WebSocket + Dify 多轮对话）

## 3. 非功能需求

### 3.1 性能需求
- 消息读取延迟：< 5 秒
- 搜索响应时间：< 3 秒
- 摘要生成时间：< 10 秒
- Bot 问答响应时间：< 10 秒（Dify 响应）
- WebSocket 事件延迟：< 3 秒

### 3.2 安全需求
- 用户凭证加密存储
- API 访问权限最小化
- 敏感信息不记录到日志
- Dify API Key 不得提交到公开仓库
- 邮件操作需授权白名单（EMAIL_AUTHORIZED_OPEN_IDS）

### 3.3 可用性需求
- 支持命令行操作
- 支持 Cherry Studio MCP 调用
- 支持 Bot WebSocket 实时监听
- 提供清晰的错误提示

## 5. 技术约束

### 5.1 平台限制
- 微信个人号 API 受限，可能需要第三方方案
- 企业微信部分功能需要管理员权限
- 飞书权限需要管理员审批
- Dify 服务仅限九号内网访问

### 5.2 数据限制
- GitHub 单文件最大 100MB
- 飞书 API 速率限制：5000 次/小时
- 邮件附件大小限制
- Dify conversation_id 30 分钟无活动自动过期

## 7. 风险与应对

### 7.1 权限审批风险
- **风险**：管理员拒绝部分权限申请
- **应对**：准备降级方案，使用机器人身份替代

### 7.2 API 限制风险
- **风险**：API 调用频率超限
- **应对**：实现请求队列和缓存机制

### 7.3 数据安全风险
- **风险**：敏感消息泄露
- **应对**：本地存储，加密敏感数据

### 7.4 企业微信限制风险
- **风险**：公司未启用消息 API
- **应对**：使用 aibot 方式发送消息，功能受限但可用

### 7.5 Dify 服务风险
- **风险**：Dify 内网服务不稳定 / 模型响应慢
- **应对**：Bot 侧设置超时、返回友好错误提示；备用降级到固定提示回复
