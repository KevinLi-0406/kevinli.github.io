### 4. 知识库拆分与格式化

#### 4.1 拆分原因
- 原始文件1300+行，Dify分段时Q和A被拆开
- 机器人检索时只找到问题，没找到答案

#### 4.2 拆分方案
- **从1个大文件拆分成22个小文件**
- **按业务模块组织**: 8个目录，22个文件
- **每个文件聚焦一个主题**，提高检索精准度

#### 4.3 目录结构
```
知识库/
├── 01-系统架构/ (1 file)
├── 02-工单管理/ (3 files)
├── 03-集成接口/ (3 files)
├── 04-业务流程/ (4 files)
├── 05-校验规则/ (3 files)
├── 06-备件与故障/ (3 files)
├── 07-特殊场景/ (3 files)
├── 08-SLA与TAT/ (2 files)
└── README.md (索引文件)
```

#### 4.4 格式化处理
**第一次格式化**: 用`---`作为分隔符
- 问题：Dify的Q&A分段功能选不上

**第二次格式化**: 改用`\n\n`（双换行）作为分隔符
- 移除所有`---`
- Q和A之间用单换行`\n`
- Q&A对之间用双换行`\n\n`
- 完全兼容Dify的通用模式（默认设置）

**最终结果**:
- 22个文件全部处理
- 216个Q&A对保持完整
- 0个`---`残留
- 0个多余空行

## 📝 经验总结

### 成功的做法
1. **先验证逻辑，再写文档** - 自动重推方案先画图验证，再写QA
2. **用Bot问答验证** - 同一个问题先问Bot再问人，发现了很多错误
3. **拆分文档** - 大文件拆成小文件，检索更精准
4. **格式化适配** - 根据Dify的分段机制调整文件格式

### 踩过的坑
1. **Q&A被拆开** - 通用模式按`\n\n`分段，Q和A被拆到不同chunk
2. **Q&A分段选不上** - Dify的Q&A分段功能有bug，参数传了None
3. **机器人进程退出** - 没有用进程管理工具，退出后不会自动重启
4. **术语不准确** - LDS/CCS是Service Store名称，不是缩写；MSD是KA不是RC

### 最佳实践
1. **QA文档格式**: Q和A之间用单换行，Q&A对之间用双换行
2. **文件拆分原则**: 按业务模块拆分，每个文件聚焦一个主题
3. **术语定义**: 第一次出现时要明确定义（如LDS、CCS、MSD等）
4. **版本管理**: 用Git管理文档变更，便于追溯
